# 0018 — Bacterial runtime and durable experimental boundaries

- Status: Accepted
- Date: 2026-09-09
- Supersedes: 0014, 0015 and 0016

## Context

The user approved replacing the ant cross-section with top-down bacteria and heritable RNNs.
The reviewed sensor/action contract produced a viable physical reproductive loop. Independent
architecture, systems and dead-code audits then found shared genetic/body randomness, inconsistent
checkpoint validation, evictable intervention provenance, leaked controller encoding and redundant
rendering work. The user authorized correction without another ecology or training expansion.

## Decision

Keep one deterministic, DOM-free top-down periodic XY kernel, shared by browser and harness.
The explicit step order remains supply/transport, local observations/inference, paid motion and
secretion, proportional uptake, maintenance/growth, contact correction and resource-funded division.
There is no map service, task dispatcher, controller fallback or reproductive fitness selector.

The physical interface owns local observations and physical efforts. Current dimensions and outputs
follow the [controller contract](../design/controller.md); the original numerical interface is
preserved in the [decision snapshot](../sources/history/2026-09-10/adr/0018-bacterial-runtime.md).
A static controller adapter owns inference, mutation, recombination, distance, inspection and
genome/private-state codecs. Persistence delegates
encoding and validation to that adapter; it does not duplicate network dimensions or inspect weights.
No dynamic plugin registry is required for a single controller.

Environment, body and genetic randomness have separate persisted streams. A zero-effect mutation
must not perturb physical placement or headings by consuming body randomness. Config validation
enforces capacity relationships used by physiology and checkpoint restoration. Restoration also
checks consistency between live bodies, organism ancestry, genome ancestry and lifetime records.

The current checkpoint contract follows the [world design](../design/bacteria.md). The v2
correction introduced explicit genetic random state and durable manual interventions.
Recent inspector events remain bounded; intervention history does not expire with that buffer.
The UI marks intervened runs as diagnostic. Competition artifacts embed controller-owned encodings,
genome hashes, source-checkpoint hash, source intervention history, resolved configuration and
source digests taken before and after the experiment. Diagnostics never promote a winner.

Rendering owns reusable Canvas/raster resources and one resize observer per mounted view.
Simulation ticks, presentation refresh and camera changes do not recreate those resources.
Remove redundant aggregation and retired path exceptions while preserving simulation purity checks.

## Consequences

Version 1 bacterial files and ant files are rejected; no adapter invents missing history or RNG
state. The existing files and ledger rows remain unchanged evidence. Seeded evolutionary results
change under the corrected random-stream contract, so the original v1 comparisons cannot certify
the new trajectories. Founder weights, physical rates and local sensor/action meanings are unchanged.

The current kernel/UI/harness separation remains. Population capacity and cumulative ancestry
storage still require measurement before claims about large or indefinite runs. The correction
does not establish adaptation or chemical cooperation and does not authorize offline training.
